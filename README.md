ERD (generated by pgAdmin 4)

ERD

Relationships
suppliers 1 → N medicines: one supplier can supply many medicines, but each medicine has one supplier. The foreign key medicines.supplier_id stores the supplier's ID instead of repeating the supplier's name and phone in every medicine row.
customers 1 → N sales: one customer can make many purchases; each sale belongs to one customer (sales.customer_id).
medicines 1 → N sales: one medicine can appear in many sales; each sale row refers to one medicine (sales.medicine_id).
Together, sales links customers and medicines (a many-to-many relationship resolved by a junction-style table).
Purpose of keys
Primary key: uniquely identifies each row. It is generated automatically by the database (GENERATED ALWAYS AS IDENTITY), so it is never typed by hand.
Foreign key: a column that references the primary key of a parent table. It guarantees that a medicine cannot point to a supplier that does not exist, and a sale cannot point to a missing customer or medicine. This avoids duplication and keeps data consistent.
Section 3: Database and Table Creation
sql
CREATE DATABASE prosper_00000000_pharmacy_system;

CREATE TABLE suppliers (
    supplier_id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    supplier_name VARCHAR(100) NOT NULL,
    phone         VARCHAR(15)  NOT NULL UNIQUE,
    city          VARCHAR(50)  NOT NULL
);

CREATE TABLE customers (
    customer_id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    full_name   VARCHAR(100) NOT NULL,
    phone       VARCHAR(15)  NOT NULL UNIQUE,
    district    VARCHAR(50)  NOT NULL
);

CREATE TABLE medicines (
    medicine_id   INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    medicine_name VARCHAR(100)  NOT NULL,
    category      VARCHAR(50)   NOT NULL,
    unit_price    NUMERIC(10,2) NOT NULL CHECK (unit_price >= 0),
    stock_qty     INT           NOT NULL DEFAULT 0 CHECK (stock_qty >= 0),
    expiry_date   DATE          NOT NULL,
    supplier_id   INT           NOT NULL,
    CONSTRAINT fk_medicines_supplier
        FOREIGN KEY (supplier_id) REFERENCES suppliers(supplier_id)
);

CREATE TABLE sales (
    sale_id     INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id INT  NOT NULL,
    medicine_id INT  NOT NULL,
    quantity    INT  NOT NULL CHECK (quantity > 0),
    sale_date   DATE NOT NULL DEFAULT CURRENT_DATE,
    CONSTRAINT fk_sales_customer
        FOREIGN KEY (customer_id) REFERENCES customers(customer_id),
    CONSTRAINT fk_sales_medicine
        FOREIGN KEY (medicine_id) REFERENCES medicines(medicine_id)
);

Parent tables (suppliers, customers) are created before child tables (medicines, sales).

Section 6: Conclusion

In this assignment I learned how to create a relational database and its tables, choosing suitable data types and constraints such as NOT NULL, UNIQUE and CHECK. I learned that primary keys uniquely identify rows and that foreign keys link child tables to parent tables, which prevents invalid references and duplicated data. I practised inserting records with auto-generated keys and retrieving data with SELECT, WHERE and ORDER BY. I used INNER JOIN, LEFT JOIN and a multi-table JOIN to combine related records, and I saw that LEFT JOIN keeps unmatched rows while INNER JOIN drops them. I learned to update records safely by checking the target rows first and always using a WHERE clause, and I learned that ALTER TABLE changes the structure of a table (renaming a column, changing a data type, adding a column), while UPDATE changes the data.
